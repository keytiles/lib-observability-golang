## TLDR

Package `kt_observability_logging` converts a `map[string]any` of labels into `[]kt_logging.Label` for [lib-logging-golang](https://github.com/keytiles/lib-logging-golang).

Use it to register **global log labels** (including the library’s default env-based set) so every log event carries the same service identity fields.

For the overall package layout and how this relates to metrics, see [Architecture-v2.0.md](Architecture-v2.0.md).

## Package

- Path: `pkg/kt_observability_logging`
- Depends on: `pkg/kt_observability` (default global labels map), `lib-logging-golang` (`kt_logging`)

## API

### `BuildLogLabels(labels map[string]any) []kt_logging.Label`

Turns each map entry into a `kt_logging.Label`:

- `nil` → string label `"<null>"`
- string → string label
- bool → bool label
- integers / floats → float label
- anything else → string label with a short “value not supported” message

### `BuildDefaultGlobalLogLabels() []kt_logging.Label`

Builds the standard global labels via `kt_observability.BuildGlobalLabelsMap()` and converts them with `BuildLogLabels`.

Default keys:

- `serviceName`
- `serviceVer`
- `host`
- `instId`

## Typical usage

```go
import (
    "github.com/keytiles/lib-logging-golang/v2/pkg/kt_logging"
    "github.com/keytiles/lib-observability-golang/v2/pkg/kt_observability_logging"
)

// Option A: library defaults from environment
kt_logging.SetGlobalLabels(kt_observability_logging.BuildDefaultGlobalLogLabels())

// Option B: custom map (still converted the same way)
kt_logging.SetGlobalLabels(kt_observability_logging.BuildLogLabels(map[string]any{
    "serviceName": "my-service",
    "serviceVer":  "1.2.3",
}))
```

You can also mix custom keys into a map and pass it to `BuildLogLabels` if your service needs extra global fields.
